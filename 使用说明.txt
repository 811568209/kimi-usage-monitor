Kimi Code / Kimi Work 本地用量监控系统（React）
更新日期：2026-11-06

一、自动更新
双击“启动统计.cmd”打开本地看板；双击“停止统计.cmd”停止后台统计。
运行期间每 5 秒自动采集调用日志，每 30 秒查询 Code 额度、查询共享月额度。
网页每 5 秒取得后台结果，不需要手动打开或刷新 Kimi 会员页面。
“更新统计”可以额外发起一次即时查询。
查询时间随实际成功响应更新；用量没有变化时，数值保持不变。
失败时显示失败状态，保留最后成功的数值和时间，不伪造新读数。
不添加开机启动或系统计划任务。重启电脑后需重新启动；需要 Node.js 24 以上。

二、数据来源
token：本机 Code 和 Work 的 usage.record 实际调用记录，包含主任务、子 Agent
和已记录的标题生成调用。分开统计非缓存输入、缓存读取、缓存写入和输出。
当前上下文长度不当成累计消耗；缺失字段不补成零。
Code 5 小时 / 周额度：通过已登录 Code 的本地服务查询。
共享月额度：主动查询 Kimi 会员接口 GetSubscription，读取实际响应中的
FEATURE_OMNI / SUBSCRIPTION 余额，其 amountUsedRatio 是已用比例，expireTime
是该余额的刷新时间。套餐信息也来自真实响应。
历史额度：从 Kimi 客户端会员日志读取，作为历史核对和接口失败时的备份。
额度变动：由相邻真实读数相减；“说明”是程序根据记录作出的判断。
额度恢复单独标记，不当成负的消费；没有对应本机调用时显示“未记录”。
费率比较的参考构成来自两端已结算样本的实际 token 构成，不用预设演示比例。
测试目录中的合成数据只用于测试，不会被运行中的网页或报告加载。

三、登录与查询
使用本机 Kimi 客户端已有登录信息，仅向已核对的 Kimi 官方端点查询。
短期访问凭据到期后，按客户端已有方式自动续期；凭据只保留在进程内存。
不修改 Kimi 配置，不保存或导出登录密钥，不安装代理或证书，不发起计费模型任务。
真正登录失效时仍需在 Kimi 客户端重新登录；页面会显示原因，并继续自动重试。

四、自动监控与自选时间
默认全自动运行，无需开始或结束采样；关闭网页也持续记录和分析。
逐次调用历史可按产品、模型/思考档位、日期筛选，并翻页查看全部本地历史。
Code 与 Work 同时运行时各自 token 分开统计，共享月额度整体扣减不能精确分摊。
可选择起止时间，并确认期间只在本机使用 Code / Work 后，推算选定时段额度。
使用范围内部首末读数匹配，未覆盖的两端不外推，不同周期分别计算。
客户端日志可能清理或轮换，本工具 data 目录独立保留已采集的数字记录。
监控未运行期间只能补采客户端仍保留的日志，无法恢复已删除的记录。

五、进阶：建立 Code / Work 对照样本（日常自动监控无需此操作）
1. 确认两端为同一账号，暂停其他电脑、手机、网页和自动任务对该账号的消费。
2. 停止现有任务；系统自动取得两次稳定的起始读数后可以开始采样。
3. 输入任务标签、勾选隔离确认，点击“开始 Code 样本”或“开始 Work 样本”。
4. 只在选中的产品执行任务。所有主任务、子任务和辅助调用停止后，点击结束。
5. 系统自动等待至少 60 秒，取得两次间隔至少 30 秒且一致的读数后结算。
   结算完成前不要开始新任务；不需要刷新 Kimi 会员页。
6. 在另一产品中用相同标签做对应任务。保持相同起始代码、模型、思考强度、
   要求与验收条件，不要让第二个产品使用第一个已经完成的结果。

两端各有一个同标签的已结算样本，就能比较任务消耗的月额度百分点及比值。
标签相同不证明完成程度相同，需要自己核对任务结果。
混用产品、账号或余额基准变化、额度触顶、字段缺失、消耗太小或结算不稳定时，
样本不会参与 token 单价估算。缓存字段缺失时，仍可在隔离与结算检查通过后记录
月额度任务成本，token 显示已知下限（≥）；不把未知字段补零。其他设备的消费
无法仅凭本机日志排除，所以仍需隔离确认。
开始采样要求 5 分钟内的稳定读数，这是统计规则，与会员有效期无关。

六、费率推算
单个样本的“月额度百分点 / 百万总 token”只适用于该样本自己的 token 构成。
拆分非缓存输入、缓存读取、输出系数至少需要 9 个同模型、同额度分段、同套餐、
同上下文分组、同思考档位的隔离样本；涉及缓存写入时至少 12 个。
思考档位未知或混合时不参与单一档位费率拟合。
构成无法区分、出现负系数或拟合误差超过 20% 时，不报告费率。
两端都有可用拟合后，以已结算样本实际 token 构成的合并值计算参考倍率。
这属于经验估计，不是官方报价，也不能自动代表任务成本或代码质量相同。

七、月 token 总额度推算（每轮采集自动更新）
每条额度观察记录按对应区间 token / 月额度已用比例增量推算月总 token。
综合结果按当前账号、套餐、周期及余额分段内全部可用区间的 token 之和 /
消耗比例增量之和计算，不平均单条推算值，也不只使用网页最近显示的记录。
一次额度变化可能对应多次调用，不能据此分摊出每次调用各自的月额度。

看板同时标明非缓存输入、缓存读取、缓存写入和输出的数量与占比，以及保持
这个构成时折算的月 token 分配；各部分不能当作独立额度或单价。
可信度显示 0%–100% 的整数，步长为 1%，是数据质量评分，不是统计概率。
自动观察无法排除其他设备和延迟结算，最高 60%；少量调用的单个自动区间最高 35%。
有高可信度区间（≥70%）时仅用高；否则用中可信度（40%–69%）；再否则全量回退。
页面标明选择档次及纳入、筛除数量；原始记录全部保留，分页不影响计算。
没有账号标识的历史记录、混合构成和长时间间隔会降低评分。
该评分不是统计概率，展示的范围是精度与波动敏感性范围，不是统计置信区间。

读数未变或消耗不足 0.05 个百分点时继续累计，后续足够变化后只结算一次。
缓存缺失时可参考同产品、模型、档位及上下文的实测构成补估，缺依据时仅折算已知量。
跨界、触顶、异常跳变仅提供很低可信度的临时估算，不参与严格费率拟合。
无调用、零 token、无可量化扣减或兼容历史时不能凭空推算。原始缓存 NULL 始终保留。
账号、套餐、周期变化与余额恢复分别分段；接口和历史日志不重叠相加。
读数未变化时继续沿用最近估算；新周期可低可信度参考同账号同套餐历史。
真正没有任何消费基准时显示 0%，取得首个依据后自动计算。
只在相同产品/模型/输入输出缓存构成与全部消费被本机覆盖的假设下适用，
属于经验推算，并非官方固定 token 配额。

九、命令行
node monitor.cjs --serve         启动看板
node monitor.cjs                 一次采集导出（先停止正在运行的监控）
node monitor.cjs --offline       只读现有日志，不主动查询接口
node monitor.cjs --stop          停止监控
node --test tests/*.test.cjs     合成数据测试，不发起模型任务

日志采集周期来自 config.json 的 intervalSeconds（默认 5 秒）；额度查询周期来自 quotaPollSeconds（默认 30 秒）。
Code 默认目录：用户目录/.kimi-code
Work 默认目录：APPDATA/kimi-desktop/daimon-share/daimon/runtime/kimi-code/home
客户端登录信息：APPDATA/kimi-desktop/daimon-share/daimon/config.json
可在 config.json 指定 codeHome、workHome、workApp 绝对路径覆盖默认位置。

十、SQLite 与会话
每轮采集写入 data/usage.sqlite；逐次调用不重复累计，5 秒周期观测独立保存。
用户输入、助手可见回复可按会话/Agent/请求/轮次关联 token；排除隐藏思考、系统提示、工具输出和附件正文。
config.json 的 collectConversationContent 控制后续正文采集；设为 false 只保留元数据和长度，已有正文不自动删除。
下载 SQLite 分析快照可在监控运行期间得到独立数据库，不需复制运行中的 WAL 文件。
表结构与 AI 分析口径见 docs/SQLITE_ANALYSIS.md。

十一、系统布局与分页
侧栏包含总览、Token 活动、调用与会话、额度推算、模型与档位、时间段分析、隔离对照、数据与运行。
所有交互数据列表默认每页 10 条，可输入 5–100 的任意整数；各列表独立记忆。
刷新或重新打开同一浏览器地址后恢复条数；分页只影响显示，分析与导出仍覆盖全部匹配数据。
活动页可切换 Code、Work 或合计，查看每日、每周、累计用量，点击热力图日期查看四类 token。
最长任务为同轮次首请求到末次用量的观测跨度，包含等待；今日未用、昨日仍连续时保留连续值。
维护 React 源码后执行 npm ci、npm run build；直接使用已有打包文件时不需要安装前端依赖。
