# Kimi 用量监控

本机 Kimi Code / Work 调用统计与共享月额度对照工具。需要 Node.js 24 或以上。

双击 `启动统计.cmd` 打开看板，双击 `停止统计.cmd` 停止。默认地址为 <http://127.0.0.1:17891>，本地日志每 5 秒采集、额度每 30 秒查询。完整操作说明见 [使用说明.txt](使用说明.txt)。

## 全自动记录与时间筛选

启动后后台持续运行，关闭网页也继续采集并保存。Code 与 Work 同时使用时分别记录各自的 token；共享月额度只能看到整体扣减，不能按 token 数量比例精确拆分。进阶隔离样本不影响日常自动监控。

逐次调用历史支持产品、模型/思考档位、日期筛选及分页。可选起止时间，并确认期间只在本机使用后，按所选时段内首末有效读数推算；覆盖不完整的边缘不外推，不同账号/周期分别列出。

客户端日志可能清理或轮换；工具的 data 目录独立保留已采集的数字记录。监控关闭期间只能补采客户端仍保留的日志。

## 月 token 总额度推算

每轮采集后，自动重新计算每条额度观察记录及当前账号、套餐、周期和余额分段内的综合月 token 总额度。

```text
区间推算 = 对应区间的完整 token 总量 ÷ 月额度已用比例的增量
综合推算 = 全部可用区间 token 之和 ÷ 全部可用区间已用比例增量之和
```

例如 10,000 token 消耗 0.1 个百分点，则保持相同使用构成时折算约为 1,000 万 token / 月。综合推算使用全部匹配数据，不受看板只显示最近 20 条记录的限制，也不对单条结果直接平均。

- 月额度是共享消耗比例：单条记录指两个额度读数匹配出的调用区间，不能把一个区间的扣减分别分摊给每次模型调用。
- 同时显示非缓存输入、缓存读取、缓存写入、输出的实际数量、占比及按当前构成折算的月 token 分配。分配数量不能当作各类 token 的独立可用额度或计费单价。
- 置信度是 0–100 的数据质量评分，考虑可用区间数、消耗信号、读数精度、结果波动与隔离确认。未经隔离确认最高 60 分，单个自动区间最高 35 分；历史账号未知、混合构成和长时间间隔会进一步限制评分。评分不是统计概率。
- 敏感性范围结合两端读数精度与区间单位消耗的 token 加权波动，不是统计置信区间；上限无法确定时明确标注。
- 读数未变或消耗不足 0.05 个百分点时继续累计，等待后续变化后一次结算，不重复计算。缺缓存、无调用、零 token、跨起点请求、额度触顶、异常跳变及超前时间的区间不参与综合推算。
- 账号切换、套餐变化、周期变化或额度恢复会开始新分段。接口与历史日志分别计算，避免重复计算同一消费；当前综合优先会员接口，历史分段保留在 JSON 中，全部观察记录可下载 CSV。

这是按本机可见日志和实际额度变化得到的经验推算。其他设备的消费与服务器延迟仍可能影响结果；它不是官方固定 token 配额。接口失败时保留最后成功记录，不伪造新读数。

## 导出与本地数据

看板提供 token、额度、对照样本与月额度推算的 CSV 下载。`reports/report.json` 包含完整分段和观察记录，`reports/report.html` 是离线报告。

`data/`、`reports/`、日志和进程状态不纳入 Git，避免提交个人使用历史。仓库中的 `config.json` 只包含通用周期和端口设置。

## 测试

```powershell
node --test tests/*.test.cjs
```

测试使用隔离目录和合成数据，包含真实本地 HTTP 服务、自动查询周期、采集恢复、导出、样本操作与服务生命周期；不发起付费模型调用。

需要人工验证网页时，运行 `node tests/browser-fixture.cjs`，打开其输出的本地地址。该测试服务使用临时目录和合成数据，与真实采集目录分离；退出后自动清理。

## SQLite 与会话关联

每轮采集会保存到 data/usage.sqlite，包含去重的逐次调用、真实额度读数、5 秒周期快照、模型/档位推算与用户/助手可见消息。可从每条调用打开关联会话。默认采集正文，仅保存在本机数据库；普通 CSV 不含正文，SQLite 分析快照包含已采集正文。

按模型、思考档位和上下文区间分别自动推算；无法分离的混用扣减或未知档位标为数据不足。

表结构、字段单位、关联规则和供 AI 使用的 SQL 示例见 [SQLite 分析说明](docs/SQLITE_ANALYSIS.md)。
